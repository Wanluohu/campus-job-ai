3.3 编写 Java 代码

(1) 通用返回结果类 Result

定义统一的响应结果类，包含状态码 code、提示信息 msg 和返回数据 data 三个字段，使用 Lombok 的 @Data 注解自动生成 getter/setter。

(2) 实体类 Food / Customer

分别对应 food 表和 customer 表，使用 @Data 注解简化代码。

(3) Repository 接口（Mapper 层）

使用 @Mapper 注解标识 MyBatis 映射接口，定义增删改查方法。例如 FoodRepository 包含：

  • Food findFood(Integer id) —— 按ID查询
  • List<Food> queryAll() —— 查询全部
  • int insertOne(Food food) —— 插入一条记录
  • int updateById(String id, int price) —— 按ID更新库存
  • int deleteById(String id) —— 按ID删除

(4) Service 层

定义业务逻辑接口和实现类。FoodServiceImpl 中实现了根据 ID 查询食品信息的业务逻辑：若食品存在则返回 code=200 及数据，否则返回 code=404 及错误提示。

(5) Controller 层

MyController1：处理前端页面请求，包括首页展示（/index）和查询请求（/check），查询成功跳转到 home.html，失败返回 index.html 并提示错误。

MyController2：提供 REST 风格的 CRUD 接口，以及页面跳转方法。包括：

  • GET /get —— 按商品ID查询食品（JSON返回）
  • GET /getall —— 获取全部食品（JSON返回）
  • GET /getall2 —— 获取全部食品并渲染列表页面
  • GET/POST /add —— 添加食品页面与表单处理
  • GET/POST /set —— 修改库存页面与表单处理
  • GET/POST /del —— 删除食品页面与表单处理

3.4 编写 MyBatis XML 映射文件

在 resources/mapper/FoodMapper.xml 中定义 SQL 语句和结果映射：

  • <resultMap> 定义数据库字段与 Java 属性的映射关系
  • <select> 定义查询语句，id 对应 Mapper 接口方法名
  • <insert> 定义插入语句
  • <update> 定义更新语句
  • <delete> 定义删除语句

七、实验总结

通过本次实验，我深入理解了以下知识点：

1. Spring Boot 项目结构：Spring Boot 采用分层架构，将代码分为 Controller（控制器层）、Service（业务逻辑层）、Repository（数据访问层）和 Entity（实体层），实现了各层之间的解耦，符合 MVC 设计模式。

2. MyBatis 持久层技术：MyBatis 通过 XML 映射文件或注解的方式将 SQL 语句与 Java 方法绑定，相较于传统的 JDBC 编程，大大简化了数据库操作的代码量。通过 resultMap 可以灵活定义数据库字段与 Java 对象属性的映射关系。

3. Thymeleaf 模板引擎：Thymeleaf 可以在 HTML 页面中通过 th:text、th:each、th:if 等属性动态渲染数据，实现了前后端的数据交互。

4. Lombok 工具：使用 @Data 注解自动生成 getter、setter、toString 等方法，减少了大量的样板代码。

5. 遇到的问题与解决方案：

  • Maven 依赖下载缓慢：配置阿里云 Maven 镜像解决。
  • Lombok 注解不生效：在 IDEA 中安装 Lombok 插件并启用注解处理器。
  • MySQL 连接失败：确保 MySQL 服务已启动，检查连接配置是否正确。

通过本次实验，我掌握了 Spring Boot + MyBatis 整合开发的基本流程，能够独立完成一个具备完整前后端交互的 Web 应用程序。
